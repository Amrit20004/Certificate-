# Templates

A template is two things: your finished certificate design as a PDF, and a map of where each value
gets printed on it.

The design is never rebuilt in code. The system copies your page verbatim and draws on top of it, so
the border, seal, signature line, logo and heading come out exactly as you designed them.

```
templates/
  internship-v1.json              the coordinate map (measured, ready to use)
  assets/
    internship-template.pdf       the blank design, built from the Canva export
    grid-overlay.pdf              generated by `npm run template:probe`
    fonts/
      Parisienne-Regular.ttf      the candidate name  — you need to add this
      Lora-Italic.ttf             the body paragraph  — you need to add this
      Lora-Regular.ttf            the certificate number — you need to add this
```

The blank design was produced from your Canva export by
`scripts/build-clean-template.py`, which removes the candidate name, the body
paragraph and the old QR image while leaving every design element in place. Run
it again whenever the design changes in Canva.

## Finding the coordinates

```bash
npm run template:probe
```

Open `assets/grid-overlay.pdf`. Every 100 points is labelled, measured from the top-left corner.
Read off where each value belongs and put the numbers in `internship-v1.json`, then re-run
`npm run seed` to push the change to the database.

## Fields

| Field | Required | What it prints |
|---|---|---|
| `candidateName` | yes | The large name |
| `body` | yes | The two-sentence paragraph |
| `certificateNumber` | no | e.g. NXT-INT-2026-000001 |
| `issueDate` | no | e.g. 31 August 2026 |
| `role` | no | The role on its own, if your design has a separate line for it |
| `qr` | yes | The verification QR code |

### Text fields

```json
{
  "type": "text",
  "x": 421, "y": 296,
  "maxWidth": 560,
  "align": "center",
  "font": "display",
  "size": 40,
  "minSize": 16,
  "color": "#101B2D"
}
```

With `align: "center"`, `x` is the centre point. With `"left"` it's the left edge, with `"right"` the
text ends at `x + maxWidth`. `y` is the text baseline.

`size` is the ideal size. If the text doesn't fit within `maxWidth`, it shrinks in half-point steps
down to `minSize`, and only truncates below that. Either way the admin sees a warning on the success
screen. Set `minSize` low enough that real long names shrink instead of truncating — 16 handles names
up to roughly 70 characters at a 560pt width.

### Paragraph fields

Same as text, plus `maxLines`, `lineHeight` and `paragraphGap`. The body wraps to `maxWidth` and
shrinks until it fits within `maxLines`. If it still overflows you get a warning telling you to either
shorten the role or raise `maxLines`.

### The QR field

```json
{ "type": "image", "x": 690, "y": 430, "width": 86, "height": 86 }
```

Here `x` and `y` are the top-left corner of the code. Don't go below about 70pt square — printed
smaller than that, phone cameras start to struggle. The code is generated at high error correction so
it still scans if the seal or a fold clips a corner.

## Fonts

Each entry can name a `file` and a `standard` fallback:

```json
"display": { "file": "templates/assets/fonts/display.ttf", "standard": "TimesRomanItalic" }
```

If the file is missing the system falls back to the standard font and logs a warning. That keeps
development working without the font files, but the output won't match your design — ship the real
fonts before issuing anything.

Only these standard fonts are available without a file: `Helvetica`, `HelveticaBold`,
`HelveticaOblique`, `TimesRoman`, `TimesRomanBold`, `TimesRomanItalic`, `Courier`, `CourierBold`.

## Changing a design

Add a new version rather than editing a published one. Bump `version` in the JSON, re-seed, and the
new version becomes the active template. Certificates already issued keep a frozen copy of the config
they were built with, so rebuilding an old certificate still reproduces the original layout.
